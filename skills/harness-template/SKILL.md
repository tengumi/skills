# Подготовка целевого репозитория

Для переноса существующего прототипа используй официальный шаблон команды.
Этот скилл подготавливает структуру, но не переносит бизнес-логику.

## Входы

Установи `name`, `stack`, путь будущего репозитория и `template_path`.
Не угадывай целевую папку и не перезаписывай существующий проект.
Имя каталога обычно записывается в `kebab-case`, Python-пакета —
в `snake_case`; точное соответствие задают правила команды.

Если запрос относится к командному опромышливанию, но шаблон неизвестен,
попроси его путь. Общая структура `src/`, проверка `/health` или GitHub Actions
не являются безопасной заменой командного шаблона.

## Приоритет источников

1. Официальные документы и шаблон команды.
2. Проверенный человеком `team-patterns.json` — только для незаданных решений.
3. Общие решения — только для нового проекта без официального шаблона,
   если пользователь прямо согласовал такой вариант.

Если `team-patterns.json` доступен, проверь `review.status == "approved"`.
Тогда используй подтверждённые зависимости, структуру, именование,
конфигурацию, журналирование, обработку ошибок, устройство агента и тестов.
Наблюдение с `confidence: low` применимо только тогда, когда его точный путь
JSON включён человеком в `review.approved_low_confidence`.
Непроверенный файл — материал для обсуждения, не стандарт для генерации.

## Работа с командным шаблоном

1. Зафиксируй его ревизию или воспроизводимый снимок содержимого.
2. Подготовь целевой репозиторий из этой структуры, не перенося секреты,
   локальные окружения, кеши и результаты запуска.
3. Составь перечень имён: сервис, пакет, репозиторий, сборка, образ,
   очередь и схема БД. Переименовывай каждую категорию по подтверждённому
   соответствию, не общей заменой всех похожих строк.
4. Сохрани доменные названия и имена внешних систем. Неизвестные реквизиты
   развёртывания не заменяй вымышленными значениями.
5. Проверь согласованность импортов, команд и структуры с документацией.
   Слои, заданные шаблоном, не удаляй только потому, что пока они пусты.
6. Подготовь навигацию через [harness-context](../harness-context/SKILL.md),
   если она отсутствует.

## Новый проект без командного шаблона

Этот раздел не применяется к командному переносу прототипа. Сначала согласуй
тип проекта и минимальный работающий результат. Допустимые типы:
`python-agent`, `python-service`, `java-service`, `frontend`.

- Python-агент: пакет с точкой входа, настройками, инструментами и промптами;
  аннотации типов; реальные тесты запуска и поведения без внешних обращений.
- Python-сервис: приложение FastAPI, схемы запросов, маршруты и бизнес-слой;
  тест рабочего маршрута; контейнер и внешние зависимости только если нужны.
- Java-сервис: согласованные версии JDK/Spring, точки входа, конфигурация,
  контроллеры, сервисы и тесты; команды через имеющуюся систему сборки.
- Веб-интерфейс: согласованный стек, компоненты, конфигурация TypeScript,
  реальные тесты и команды установки, разработки и проверок.

Не добавляй неподтверждённую модель, API, базу, брокер или платформу публикации.
Не выдавай заглушку за работающую реализацию. Версии и зависимости выбирай
по условиям проекта, а не по старым числам из примера.

Создай `AGENTS.md` не длиннее 120 строк и полезные документы `docs/harness/`.
Каждая команда `Makefile` должна выполнять реальное действие. Невыполненные
согласованные работы занеси в очередь задач по действующей схеме, не скрывай
их за неучтёнными `TODO`. При отсутствии проверенных командных образцов
предложи [harness-extract-patterns](../harness-extract-patterns/SKILL.md)
как отдельную возможность, а не обязательную задержку.

## Проверка и передача

В разрешённой среде проверь установку с чистого состояния, импорт точки входа
и штатную команду проверок. Не обходи сетевые ограничения среды и не читай
секреты. Если команду выполнить нельзя, укажи точную непроверенную часть.

После проверки подготовь исходный коммит в разрешённом объёме и передай
перенос прототипа [harness-lead](../harness-lead/SKILL.md), обычную очередь —
[harness-work-session](../harness-work-session/SKILL.md).
Успешные результаты подготовки используй повторно, пока их входы не изменились:
новый обязательный круг установки и тестов не нужен.

В отчёте перечисли источник шаблона, созданные файлы, заменённые категории имён,
проверенные команды и нерешённые вопросы. Подготовленный репозиторий ещё
не означает завершение переноса, этапов B/C или готовность к выпуску.
