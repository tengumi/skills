# Рабочие скиллы

Здесь 19 скиллов с необходимыми пояснениями, шаблонами и программами.
Подключите их к своему Кодовому агенту и начните с `harness-lead`.
Он выбирает следующий шаг и вызывает профильный скилл сам.

## Как использовать

1. Подключите каталоги с `SKILL.md` принятым в команде способом.
2. Оставьте весь `harness-kit-prom/` доступным агенту. Параметр `harness_kit`
   указывает на его корень: там схемы, документы команды и Tasks MCP.
3. Подготовьте входы по [ONBOARDING.md](../ONBOARDING.md) и используйте
   [стартовый запрос](../README.md#запрос-для-старта).

Соседний полный kit разработки не нужен. Не подключайте одновременно
одноимённые скиллы из другой редакции.

## Для чего нужны программы

- `harness-lead/scripts/` — проверить план, посчитать контрольные суммы,
  получить сводку состояния и взять задачу через Tasks MCP.
- `harness-production-readiness/scripts/` — проверить состав собранного
  пакета и запуск/остановку процесса.
- `harness-golden/scripts/` — проверить структуру эталонного набора,
  если создание такого набора входит в запрос.

Пути к программам определяются относительно установленного `SKILL.md`,
а не текущего рабочего каталога. Нужен Python 3.12; для проверки плана —
зависимости из [requirements.txt](harness-lead/scripts/requirements.txt).
Их устанавливают в отдельную среду инструментов разрешённым способом,
не добавляя в зависимости создаваемого сервиса. Эти программы не требуют
Node.js или API выбора модели. Работа с POSIX-процессами рассчитана на Linux/macOS.

`references/` читается только по необходимости конкретного шага.
`scripts/` запускается для нужной проверки, а не автоматически после каждой задачи.
Наличие программ не заменяет проверку результата и не гарантирует защиту среды.

Tasks MCP и необязательный watcher настраиваются отдельно по инструкциям
в [корне комплекта](../README.md). Если среда не предоставляет субагентов,
маршрут выполняется последовательно.
