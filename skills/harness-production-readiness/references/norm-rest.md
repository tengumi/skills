# НОРМ REST: клиент из OpenAPI

Применяй, когда владелец выбрал REST и правила команды предусматривают генерацию клиента из официальной OpenAPI. Сначала прочитай [общие правила](integration-patterns.md). Классы, операции и способ подключения определяй по схеме и текущей версии клиента.

## Входы

Нужны `operationId`, методы и пути, типы запросов/ответов/ошибок, `info.version` и хеш OpenAPI, пакет и импорт, префикс и обязательные настройки, авторизация, передача контекста, подтверждённые повторы, тайм-ауты и управление ресурсами. Версия пакета клиента не обязательно равна версии OpenAPI.

Сначала проверь подходящий готовый клиент общей библиотеки или владельца. Если он опубликован, применяй [правила готового SDK](agent-api.md), не создавай второй экземпляр генерации. При локальной генерации зафиксируй версию генератора, хеш схемы, команду с параметрами, каталог результата и правила хранения в Git. Генератор без версии не обеспечивает повторяемость.

## Сборка подключения

```text
Префикс настроек → GeneratedConfiguration
Создание клиента(GeneratedConfiguration) → ApiClient → TypedApi
Контейнер зависимостей → ConsumerService(api: TypedApi)
Операция(GeneratedRequest, RequestContext) → GeneratedResponse
```

Названия в схеме условные, реальные классы бери из выбранного пакета. Привязывай сгенерированную `Configuration` к префиксу только если её тип поддерживается текущим загрузчиком команды. Создающий код владеет `ApiClient` и ожидает асинхронное закрытие.

Использующий сервис создаёт DTO и вызывает точный метод клиента. Не повторяй вручную URL/тело запроса и не добавляй дублирующую обёртку без причины. Контекст передаётся в поле или заголовок конкретного вызова способом, который поддерживает клиент. Время жизни общего пула и обязательность подключения при запуске определяет целевой контракт.

## Проверка

Проверь импорт настоящего клиента, соответствие схеме и отсутствие неожиданных различий при повторной генерации. Через подмену транспорта проверь получение клиента из приложения, сериализованные путь/тело/контекст, ошибки и закрытие владельцем. Ожидаемые данные имеют источник в схеме или материалах владельца. Проверь изоляцию контекстов; общая проверка приложения использует ту же регистрацию зависимостей.

Имена операций, заголовки, префиксы, повторы, размеры пакетов и версии библиотек должны быть подтверждены для целевого сервиса.
