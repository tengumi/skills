# API другого агента: готовый SDK

Применяй, если владелец API публикует версионированный клиент. Сначала прочитай [общие правила](integration-patterns.md). Версию клиента и доступные операции сверяй с контрактом целевого сервиса.

## Контракт

Запиши пакет/импорт, прямую зависимость с совместимым диапазоном, установленную версию, точные классы/методы/типы ошибок, базовый URL, передачу арендатора, сессии и статуса. Прямой импорт не должен случайно работать только из-за транзитивной зависимости общей библиотеки. Совпадение названия метода без сверки версии недостаточно.

Версионированного SDK с доступными типами, операциями, метаданными и контрактом владельца может быть достаточно. Не требуй исходники его закрытого генератора ради происхождения. Неподтверждённое так и помечай. Для локальной генерации применяй [отдельные правила](norm-rest.md).

## Сборка подключения

```text
Настройки API + собственный/заимствованный транспорт → создание OwnerSdkClient
Контейнер зависимостей → AgentService(client: OwnerSdkClient)
Операция(OwnerRequest, RequestContext) → OwnerResponse
```

Это условная схема; методы и типы бери из пакета владельца. Создающий код получает узкие настройки интеграции, не все настройки приложения. Бизнес-код не создаёт SDK скрыто внутри замыкания графа. Явно внедрённая функция создания в адаптере с ограниченным временем операции допустима.

Общий HTTP-пул без состояния запроса может жить в `APP`, если SDK принимает внешний транспорт. Его закрывает владелец; обёртка не закрывает заимствованный пул. Собственные ресурсы SDK освобождаются по API его версии. Контекст передаётся каждому вызову, не меняет общие заголовки. Значения сессии/статуса и подстановка другого арендатора определяются контрактом.

Для намеренно отключённой интеграции не регистрируй вызываемый инструмент либо сделай явный отключённый путь. Не внедряй `None` как обычный клиент. Для включённой интеграции проверь обязательные настройки.

## Проверка

Проверь настоящий SDK через точку подмены его транспорта: DTO, путь, тело, контекст и ошибки из независимого контракта/фикстуры. Сверь прямую зависимость, получение клиента из настоящего приложения, принадлежность пула, закрытие и параллельные контексты.

Общая локальная проверка использует экспортируемое приложение и его реальный набор зависимостей. Проверки сериализации и управления ресурсами дополняют друг друга; они не доказывают доступность соседнего сервиса в рабочей среде. Не переноси правку префикса URL, статусы, смягчение ошибок и область `APP` без подтверждения. Неизвестный API не становится подтверждённым от заполненного URL.
