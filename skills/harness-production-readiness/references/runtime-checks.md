# Проверки собранного артефакта и локального процесса

Две независимые утилиты на стандартной библиотеке Python 3.12+. Они не меняют
очередь Tasks MCP, не строят/устанавливают пакет и не принимают решение о выпуске.
Обе печатают JSON в stdout; код 0 означает успешную указанную проверку, 1 — отказ.
Входные файлы не переписываются. Примеры ниже — образцы, не результаты проверки
вашего сервиса.

Команды ниже выполняются из корня `harness-kit-prom`. Программы находятся в
`scripts/` скилла; отдельные копии утилит не требуются.

## Wheel inventory

```bash
python3 skills/harness-production-readiness/scripts/wheel_inventory.py \
  /absolute/path/dist/demo-1.0-py3-none-any.whl \
  --manifest /absolute/path/wheel-manifest.json
```

Manifest содержит точные корневые каталоги архива и обязательные относительные
пути с SHA-256. Хеши берутся из ранее зафиксированного контракта/безопасных
ресурсов, а не генерируются из проверяемого wheel. Пример для ресурса с байтами
`Frozen synthetic prompt\n`:

```json
{
  "schema_version": 1,
  "allowed_roots": ["demo", "demo-1.0.dist-info"],
  "required_files": {
    "demo/resources/prompt.txt": "e28430b15a004980b6c03d0be3eec5db91894d7fe578d7f3936c6f50bbb3aeed"
  }
}
```

Формат строгий: неизвестные поля, дубли ключей JSON, небезопасные пути и хеши
неверного формата отвергаются. `allowed_roots` разрешает дополнительные файлы
внутри перечисленных корней, но не отменяет запреты. Чтобы заморозить весь
runtime, включите в `required_files` все его файлы. Обязателен ровно один
`.dist-info` с `METADATA`, `WHEEL`, `RECORD`; семантика RECORD не проверяется.

До распаковки содержимого проверяются пути, дубли (включая case-fold коллизии),
необычные типы ZIP-entries, symlinks, шифрование и лимиты. Запрещены БД и
sidecars, кеши, тесты, `.env*`, известные имена ключей/credentials/secret files.
Если предварительная проверка не прошла, тела entries вообще не читаются.
Файлы архива не извлекаются на диск. Из разрешённых ограниченных по размеру
entries считаются hashes; отдельно ищутся известные маркеры закрытых ключей и
абсолютных исходных путей. HTTP URL не принимается за Windows-путь.

По умолчанию: archive 64 MiB, одна entry 8 MiB, суммарно 64 MiB, 10 000 entries.
API `check_wheel(wheel: Path, manifest: dict, *, limits=Limits())` позволяет
изменить лимиты. `load_manifest(path)` читает только явно переданный JSON
до 1 MiB; final-path symlinks и имена секретных файлов отклоняются. Ни prototype,
ни `.env`, ни окружение не обходятся. Manifest — доверенный несекретный вход;
утилита не предназначена для проверки файлов, которые одновременно меняет
другой процесс. Проверка известных маркеров не гарантирует отсутствия всех
секретов и не заменяет security review.

## Process smoke

```bash
python3 skills/harness-production-readiness/scripts/process_smoke.py \
  --health-url http://127.0.0.1:8123/healthz \
  --ready-url http://127.0.0.1:8123/readyz \
  --success-exit-code 0 \
  --shutdown-stdout-marker 'application cleanup complete' \
  -- /absolute/installed/bin/python -I -m demo \
  --host 127.0.0.1 --port 8123 --database '{workdir}/records.sqlite'
```

Запускается ровно одна явно заданная команда без shell. Исполняемый файл должен
иметь абсолютный путь; окружение дочернего процесса пустое (`env={}`), stdin и
stderr отключены. По умолчанию cwd — новый временный каталог, удаляемый после
проверки. `--cwd /absolute/safe/workdir` оставляет выбор и очистку рабочего
каталога вызывающему. `{workdir}` в аргументах заменяется на фактический cwd.
Не помещайте секреты в argv; утилита не читает env/config и не печатает команду.
Для доказательства installed artifact выбирайте Python установленного окружения,
`-I` и cwd вне исходников. Сам smoke не доказывает происхождение импортированного
модуля — это отдельная проверка сборки/установки.

GET-probes идут только к numeric loopback по HTTP, без DNS-имён, прокси,
перенаправлений, credentials, query и чтения тела ответа. Нужен ожидаемый HTTP
status, а не произвольный непустой ответ. Уже занятый/непроверенный порт означает
отказ до запуска; чужой listener не останавливается. Проверка URL **не является
сетевой песочницей ОС**: запускайте только проверенный код, настроенный на
loopback и синтетические зависимости. Child сам может обращаться к сети, если
так запрограммирован; утилита этого не ограничивает.

`--success-exit-code` обязателен и может повторяться: выбирайте подтверждённую
политику именно своего runtime, не добавляйте `-15` автоматически. Проверяются
прекращение собственной POSIX process group, закрытие проверенных портов,
отсутствие преждевременного завершения и forced kill. При превышении timeout
собственной группе посылается SIGKILL для очистки, но такой прогон всегда failed.
Нет поиска процессов или kill по имени/порту; child не должен daemonize/выходить
из созданной группы. На не-POSIX платформах запуск отклоняется.

`--shutdown-stdout-marker` и `--forbidden-stdout-marker` — необязательные
runtime-specific строки: анализируются после запроса остановки, в памяти остаются
только булевы совпадения и короткий хвост до длины маркера. Логи и payload не
сохраняются/не печатаются. Выбирайте уникальные markers, появляющиеся именно
после cleanup, и направляйте их в stdout; stderr намеренно не анализируется.
Без markers результат подтверждает код выхода/очистку процесса/портов, но
не доказывает application-level graceful cleanup. С markers доказательство
зависит от корректности выбранного runtime-контракта, не от названия утилиты.

API:

```python
result = run_smoke(
    ["/absolute/installed/bin/python", "-I", "-m", "demo", "--host", "127.0.0.1"],
    cwd=Path("/absolute/safe/workdir"),
    probes=(Probe("http://127.0.0.1:8123/healthz"), Probe("http://127.0.0.1:8123/readyz")),
    shutdown_policy=ShutdownPolicy((0,), stdout_markers=("application cleanup complete",)),
)
```

Это bounded smoke, не runner: нет restart, external evaluator, scheduler,
создания config, бизнес-запросов или универсальной политики graceful shutdown.
