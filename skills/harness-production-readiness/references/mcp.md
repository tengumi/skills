# MCP: протокол и ограниченная сессия

Применяй для выбранного владельцем MCP с известными адресом и контрактом инструментов. Сначала прочитай [общие правила](integration-patterns.md). Используй транспорт, указанный в контракте MCP-сервера; не выбирай SSE автоматически.

## Входы

Нужны пакет/импорт SDK, совместимый диапазон и зафиксированная версия, транспорт и адрес, названия инструментов, схемы аргументов/ответов/ошибок, авторизация и контекст, правила инициализации/поиска инструментов, повторного использования сессии, тайм-аутов, повторов и закрытия. Каталог одной системы не заменяет контракт другой.

## Сборка подключения

```text
Типизированные настройки → McpConfig
Контейнер зависимостей → сервис с SessionFactory и McpConfig
Операция с контекстом запроса:
  открыть транспорт
    открыть ClientSession → выполнить требуемую инициализацию
      вызвать точный инструмент → проверить результат
    закрыть сессию
  закрыть транспорт
```

Это схема, не готовая команда. В подтверждённом SSE-варианте используются вложенные контекстные менеджеры `sse_client(...)` и `ClientSession(read, write)`. Для другого транспорта нужны API выбранной версии SDK.

Функция создания может находиться в адаптере, а сессия открываться внутри операции или группы вызовов. Контейнер внедряет эту функцию/сервис, отдельный создающий компонент на каждый поток не обязателен. Объект создания в `APP` допустим без раннего сетевого согласования; время жизни активной сессии определяется состоянием, параллельностью и контрактом сервера.

Перед использованием разбирай `isError`, типы содержимого и схему ответа. Не всякое содержимое — JSON-текст. Ошибка содержит безопасную категорию, не сырой `result.content`. Превращение ошибки в успешный текст допустимо только по подтверждённой семантике. Повторы, группы вызовов и запасные варианты должны соответствовать целевому контракту.

## Проверка

Сохрани настоящий SDK, создание клиента и регистрацию зависимостей, подменив внешнюю сторону транспорта. Воспроизведи требуемую последовательность: соединение/согласование, `initialize` и уведомление, поиск или вызов инструмента, результат/ошибка, закрытие. Для SSE учти объявляемый адрес, если SDK его использует.

Проверь неверное содержимое, недоступность, тайм-аут, отмену и освобождение ресурсов на применимых путях. Схемы и ожидаемые ответы должны иметь независимый источник. Подмена одного `call_tool` не доказывает правильный жизненный цикл. Общая проверка приложения подтверждает отсутствие ранней сети, кроме явно обязательного при запуске подключения.
