# Как начать опромышливание

Не нужно самостоятельно выбирать скилл для каждого шага. Начните с
`harness-lead`: он изучит входы, составит план, выполнит перенос и проверки,
сохранит состояние и продолжит после паузы.

## 1. Подготовьте входы

- **Прототип:** путь к рабочему коду и точка входа. Укажите commit/tag, если
  знаете. Если Git нет, используйте неизменяемую копию только для чтения.
- **Целевой репозиторий:** создайте его из официального шаблона команды.
- **Правила команды:** если они уже есть в целевом репозитории, не заменяйте их
  файлами из комплекта. Иначе используйте согласованные документы из `team-docs/`.
- **Контракты подключений:** приложите доступные описания API, MCP, БД и примеры
  правильного использования общей библиотеки. Старое опромышливание этого же
  агента не требуется и не должно становиться источником готового кода.

Промпты, схемы и порядок шагов заранее пересказывать не нужно — Harness
разберёт прототип сам. До чтения исходников соблюдите [правила безопасности](SAFETY.md).

## 2. Заполните паспорт подключений

Скопируйте [форму](PRE-INDUSTRIALIZATION-SPEC.md) в целевой репозиторий как
`docs/harness/pre-industrialization-spec.md`. Если файл уже есть, дополните
его без потери существующих записей.

Напишите своими словами, что должно измениться. Например: «Сейчас агент читает
документы из папки, а в сервисе должен получать их из Библиотеки по ID».
Добавьте пути к описаниям нужных систем. Точные операции и поля агент извлечёт
из доступных документов; неизвестное оставьте как `НЕИЗВЕСТНО`.
`НЕТ` означает, что подключение не нужно. Секретные значения не указывайте.

Если нужна помощь, отправьте отдельный запрос:

> Помоги заполнить `<target>/docs/harness/pre-industrialization-spec.md`
> по форме `<harness-kit-prom>/PRE-INDUSTRIALIZATION-SPEC.md`.
> Прототип: `<путь>`, шаблон: `<путь>`, правила и контракты: `<пути>`.
> Прочитай только эти источники. Не читай `.env`, значения окружения, ключи
> и секреты; не запускай код, установку, тесты или внешние вызовы.
> Меняй только паспорт, сохраняя мои записи. Не придумывай операции, реквизиты
> и решения. При нехватке моих решений задавай до трёх понятных вопросов за раз.
> Отмечай источники подтверждённых сведений. Опромышливание пока не запускай.

Полностью заполнять данные о развёртывании до этапа A не требуется.
Отсутствующий контракт уточняется перед реализацией именно этой интеграции.
Техническую карту `data-boundaries.md` и очередь задач составит Harness.

## 3. Подключите инструменты

1. Подключите каталоги из [skills/](skills/README.md) способом, принятым
   в вашей среде Кодового агента. Не подключайте вторую редакцию этих же скиллов.
2. Настройте [Tasks MCP](mcp-servers/tasks-mcp/README.md) с режимом
   `out_of_band`. Его состояние хранится вне целевого репозитория.
3. Подготовьте Python и зависимости инструментов по [инструкции скиллов](skills/README.md).
   Версию Python сервиса возьмите из шаблона. Для проекта на uv проверьте:

```bash
uv --version
uv python find <версия-Python-из-шаблона>
```

Доступ к внутренним пакетам настраивается владельцем среды без передачи секретов
агенту. Зависимости и установки выполняются только разрешённым способом.

Если команды нужно выполнять на другой машине, настройте
[watcher](harness-watcher/SETUP-GUIDE.md). Из его папки:

```bash
python3 watcher.py add <имя-проекта>
python3 watcher.py start <имя-проекта> --check
python3 watcher.py start <имя-проекта>
```

Самому watcher не нужна установка библиотек. Мастер сохранит пути и рецепт
подготовки окружения сервиса; зависимости для него нужно заранее сделать
доступными офлайн. Дополнительный кодовый агент на машине watcher не нужен.

## 4. Запустите маршрут

Используйте [стартовый запрос из README](README.md#запрос-для-старта).
В `harness_kit` укажите абсолютный путь к этой папке `harness-kit-prom`.
В среде с поддержкой `/goal` тот же запрос можно использовать для длительного
прогона. Этот комплект сам не добавляет такую возможность в среду.

После паузы достаточно: «Продолжай `$harness-lead` с сохранённого состояния».
Новая сессия для каждой задачи не нужна. Актуальные статусы проверяются в Tasks MCP,
поэтому `tasks.json` может не менять их прямо в файле.

Harness продолжает обычные действия в уже разрешённом объёме. Человек нужен
при изменении поведения прототипа, существенном конфликте контрактов, новом
доступе либо действии вне разрешений. Рабочие внешние вызовы, изменения общей
БД и развёртывание требуют отдельного согласования.

Готовый код B, внешняя проверка C и разрешение на выпуск — разные результаты.
Недоступность стенда не отменяет сделанную офлайн-часть, но и не доказывает
готовность сервиса к промышленной эксплуатации.
