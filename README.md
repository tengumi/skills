# Harness — комплект для опромышливания

Здесь только то, что нужно для рабочего прогона. Папку можно перенести целиком
на другую машину: соседний репозиторий разработки Harness не требуется.

Начните с [ONBOARDING.md](ONBOARDING.md). Подключите скиллы из этой папки
и передайте работу `harness-lead`: он сам проведёт по этапам A → B → C.

## Что внутри

| Папка или файл | Для чего нужен |
|---|---|
| [skills/](skills/README.md) | Рабочие скиллы, пояснения и необходимые программы проверки |
| [PRE-INDUSTRIALIZATION-SPEC.md](PRE-INDUSTRIALIZATION-SPEC.md) | Форма паспорта подключений, которую нужно заполнить перед стартом |
| [team-docs/](team-docs/README.md) | Правила архитектуры, структуры и написания кода команды |
| templates/ | Шаблоны проектных инструкций, плана и контрактов; схема проверки задач |
| [mcp-servers/tasks-mcp/](mcp-servers/tasks-mcp/README.md) | Сервер, который хранит состояние задач между шагами и сессиями |
| [harness-watcher/](harness-watcher/README.md) | Выполнение команд на другой машине, если напрямую это невозможно |
| [SAFETY.md](SAFETY.md) | Правила обращения с секретами и границы защиты |

`scripts/` и `lib/` — не материалы разработки: это программы, нужные при
выполнении проверок и работе watcher. Их нельзя удалить без потери функций.
`references/` содержит пояснения для отдельных шагов, а не историю проекта.

Тестов разработки Harness, учебных прототипов, старых отчётов, презентаций,
экспериментального выбора моделей и настроек конкретного приложения здесь нет.
Создание эталонных наборов через `harness-golden` — дополнительная возможность,
а не обязательный этап каждого переноса.

## Что нужно отдельно

Сам прототип, официальный шаблон сервиса, целевой репозиторий, доступные контракты
интеграций и настроенная среда выполнения. Этот комплект не содержит
корпоративных зависимостей, учётных данных и доступов к внешним системам.

Для программ скиллов нужен Python 3.12. Зависимость проверки плана указана в
[requirements.txt](skills/harness-lead/scripts/requirements.txt); её готовят
в среде инструментов отдельно от сервиса. Tasks MCP и watcher используют
стандартную библиотеку Python. Версию Python самого сервиса задаёт шаблон команды.

## Запрос для старта

> Используй `$harness-lead` из `harness-kit-prom/skills/`.
> prototype=`<путь к прототипу>`, target=`<путь к целевому репозиторию>`,
> team_template=`<путь к шаблону>`, harness_kit=`<полный путь к harness-kit-prom>`,
> team_docs=`<путь к правилам команды>` при необходимости,
> execution=`<direct или watcher>`.
> Разрешаю необходимые безопасные офлайн-изменения в целевом репозитории,
> включая файлы зависимостей и шаблона. Веди весь маршрут самостоятельно.
> Прошлую реализацию этого агента не используй как источник кода.
> Внешние вызовы, общую БД и развёртывание согласовывай отдельно.

Параметр `harness_kit` указывает **на эту папку**, несмотря на её имя.
Не подключайте одновременно одноимённые скиллы из других комплектов.

Сначала сохраняется поведение прототипа (A), затем проверяется собранный сервис
без рабочих внешних вызовов (B), после — разрешённые внешние проверки (C).
Завершённый B сам по себе не означает готовность к выпуску.

Это отдельная поставка: изменения в исходном kit не обновляют её автоматически.
При следующем обновлении сохраните свои записи и настройки до замены файлов.
