# Team docs

Нормативная документация команды для production-доводки через Harness.

- Эти файлы принадлежат команде и для Harness являются read-only.
- Изменять их можно только отдельным решением владельца документации.
- Они описывают целевую production-архитектуру, но не доказывают, что endpoint, протокол, worker, БД или другой слой уже есть в прототипе.
- Применимость требований устанавливается по target repo, team template и production-плану.

Файлы: [архитектура](architecture.md), [конфигурация](configuration.md), [соглашения](conventions.md), [настройка окружения](dev-setup.md), [MLE PEP8](mle-pep8.md), [структура проекта](project_structure.md), [обязательные правила](rules.md).

## Открытые вопросы исходного документа

- В конфигурации указан персональный абсолютный путь к конкретному проекту; его переносимость не определена.
- В архитектуре остались доменные примеры risk-assessment и `RisksState`; неясно, нормативны они или иллюстративны.
- Область требования Advanced Alchemy для Repository, Data Model и DTO сформулирована неоднозначно.
- Не разведены назначения собственного API-клиента в `libs/` и клиентов в `generated/`.
- Требования Python `3.12.3` и `>=3.12` требуют явного правила приоритета.
- «Весь код покрыт юнит-тестами» и порог 80% требуют единой трактовки.
- Не указано, должна ли содержащая секреты `.run/` быть только локальной и незакоммиченной.
- В примере удаления стоп-слов используется `in`, а не `not in`.
- Утверждение о создании нового экземпляра коллекции через `+=` требует технического уточнения.

До решения владельцем эти места сохранены без скрытых исправлений.
